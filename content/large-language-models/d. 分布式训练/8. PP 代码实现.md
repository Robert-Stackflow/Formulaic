title: PP 代码实现
description: 介绍流水线并行（Pipeline Parallel, PP）的基本原理及其在深度学习中的代码实现方法
---

- 明确核心概念：

	- pp_size=4：模型被切分为 4 个 stage，分别部署在 GPU0、GPU1、GPU2、GPU3 上（GPU3 是最后一个 stage，负责反向传播的起点）。

	- micro-batch (mb)：将一个大 batch 拆分为多个小 batch 串行处理（假设总 mb 数量足够多，如 mb1、mb2、mb3、mb4、mb5...）。

	- 核心规则：
		- 前向传播（FWD）：数据从 GPU0 → GPU1 → GPU2 → GPU3 依次传递激活输出；
		- 反向传播（BWD）：梯度从 GPU3 → GPU2 → GPU1 → GPU0 依次传递；
		- 通信触发：前向完成后发送激活输出，反向完成后发送梯度；
		- 每个 GPU 同一时间只做一件事：要么前向、要么反向、要么等待；
		- 前向和反向严格拆分为不同时间步，不混在同一步；
		- 数据/梯度接收完成后，下一个时间步才能执行对应计算。

### 基础设定

- pp_size=4，对应 GPU0（stage1）、GPU1（stage2）、GPU2（stage3）、GPU3（stage4，最后一个 stage）；
- 每个 GPU 同一时间只能处理：前向 / 反向 / 等待；
- Warmup：流水线“填数据”阶段，只有前向、无反向；
- Steady：流水线满载，前向和反向交替；
- Cool down：流水线“清空数据”阶段，只有反向、无前向

### 二、详细阶段

#### 1. Warmup 阶段（流水线填充，仅前向）

Warmup 的核心是从 GPU0 开始，逐个 GPU 启动前向传播，直到最后一个 GPU（GPU3）完成第一个 mb 的前向，此阶段无任何反向传播（因为还没有 mb 走完完整前向）

| 时间步 | GPU0 (stage1)                        | GPU1 (stage2)                        | GPU2 (stage3)                        | GPU3 (stage4)               |
| ------ | ------------------------------------ | ------------------------------------ | ------------------------------------ | --------------------------- |
| t1     | 处理 mb1 前向 → 发送 mb1 激活到 GPU1 | 等待 GPU0 的 mb1 激活                | 等待 GPU1 的数据                     | 等待 GPU2 的数据            |
| t2     | 处理 mb2 前向 → 发送 mb2 激活到 GPU1 | 处理 mb1 前向 → 发送 mb1 激活到 GPU2 | 等待 GPU1 的 mb1 激活                | 等待 GPU2 的数据            |
| t3     | 处理 mb3 前向 → 发送 mb3 激活到 GPU1 | 处理 mb2 前向 → 发送 mb2 激活到 GPU2 | 处理 mb1 前向 → 发送 mb1 激活到 GPU3 | 等待 GPU2 的 mb1 激活       |
| t4     | 处理 mb4 前向 → 发送 mb4 激活到 GPU1 | 处理 mb3 前向 → 发送 mb3 激活到 GPU2 | 处理 mb2 前向 → 发送 mb2 激活到 GPU3 | 处理 mb1 前向（无激活发送） |

Warmup 结束标志：GPU3 完成第一个 mb（mb1）的前向，准备开始反向

---

#### 2. Steady 阶段（前向一步、反向一步，严格拆分）

规则：
- 每个时间步只做前向 或 只做反向；
- 本步收到数据/梯度 → 下一时间步直接执行；
- GPU3 反向完成 → 发送梯度 → 下一时间步 GPU2 可执行反向；
- 以此类推，梯度从后往前传递。

| 时间步 | GPU0 (stage1)                            | GPU1 (stage2)                         | GPU2 (stage3)                         | GPU3 (stage4)                         |
| ------ | ---------------------------------------- | ------------------------------------- | ------------------------------------- | ------------------------------------- |
| t5     | 前向：处理 mb5 → 发送 mb5 激活到 GPU1    | 前向：处理 mb4 → 发送 mb4 激活到 GPU2 | 前向：处理 mb3 → 发送 mb3 激活到 GPU3 | 前向：处理 mb2                        |
| t6     | 等待 GPU1 的 mb1 梯度                    | 等待 GPU2 的 mb1 梯度                 | 等待 GPU3 的 mb1 梯度                 | 反向：处理 mb1 → 发送 mb1 梯度到 GPU2 |
| t7     | 前向：处理 mb6 → 发送 mb6 激活到 GPU1    | 前向：处理 mb5 → 发送 mb5 激活到 GPU2 | 前向：处理 mb4 → 发送 mb4 激活到 GPU3 | 前向：处理 mb3                        |
| t8     | 等待 GPU1 的 mb1 梯度                    | 等待 GPU2 的 mb1 梯度                 | 反向：处理 mb1 → 发送 mb1 梯度到 GPU1 | 反向：处理 mb2 → 发送 mb2 梯度到 GPU2 |
| t9     | 前向：处理 mb7 → 发送 mb7 激活到 GPU1    | 前向：处理 mb6 → 发送 mb6 激活到 GPU2 | 前向：处理 mb5 → 发送 mb5 激活到 GPU3 | 前向：处理 mb4                        |
| t10    | 反向：处理 mb1 → 无梯度可发（最前stage） | 反向：处理 mb1 → 发送 mb1 梯度到 GPU0 | 反向：处理 mb2 → 发送 mb2 梯度到 GPU1 | 反向：处理 mb3 → 发送 mb3 梯度到 GPU2 |

Steady 阶段核心特征：
- 前向和反向严格拆分为不同时间步，不混合；
- 梯度必须在上一步收到，当前步才能执行反向；
- 流水线满负荷：总有 GPU 在做前向，同时有 GPU 在做反向；
- GPU3 无前向发送，只做前向计算 + 反向计算并发送梯度。

---

#### 3. Cool down 阶段（流水线清空，仅反向）

当所有 mb 的前向传播完成后，进入 Cool down 阶段：无新的前向任务，仅处理剩余的反向传播，直到所有 mb 的反向完成。

假设总 mb 为 mb1~mb8，前向全部完成，只做反向：

| 时间步 | GPU0 (stage1)              | GPU1 (stage2)                         | GPU2 (stage3)                         | GPU3 (stage4)                         |
| ------ | -------------------------- | ------------------------------------- | ------------------------------------- | ------------------------------------- |
| t11    | 等待 GPU1 的 mb6 梯度      | 等待 GPU2 的 mb6 梯度                 | 等待 GPU3 的 mb6 梯度                 | 反向：处理 mb8 → 发送 mb8 梯度到 GPU2 |
| t12    | 等待 GPU1 的 mb7 梯度      | 等待 GPU2 的 mb7 梯度                 | 反向：处理 mb6 → 发送 mb6 梯度到 GPU1 | 反向：处理 mb7 → 发送 mb7 梯度到 GPU2 |
| t13    | 等待 GPU1 的 mb8 梯度      | 反向：处理 mb6 → 发送 mb6 梯度到 GPU0 | 反向：处理 mb7 → 发送 mb7 梯度到 GPU1 | 无任务                                |
| t14    | 反向：处理 mb6             | 反向：处理 mb7 → 发送 mb7 梯度到 GPU0 | 反向：处理 mb8 → 发送 mb8 梯度到 GPU1 | 无任务                                |
| t15    | 反向：处理 mb7             | 反向：处理 mb8 → 发送 mb8 梯度到 GPU0 | 无任务                                | 无任务                                |
| t16    | 反向：处理 mb8（全部完成） | 无任务                                | 无任务                                | 无任务                                |

Cool down 结束标志：GPU0 完成最后一个 mb（mb8）的反向传播，所有 GPU 无剩余任务。
