# 1. 浮点精度（Floating-Point Precision）

**精度指的是模型内部使用的数据类型精细度，也就是 “数字有多精细”**

常见精度：

| 格式               | 位宽      | 用途                |
| ---------------- | ------- | ----------------- |
| FP32             | 32 bits | 训练标准精度            |
| FP16             | 16 bits | 训练与推理常用精度         |
| BF16             | 16 bits | 更宽动态范围，训练首选       |
| FP8 (E4M3, E5M2) | 8 bits  | 新 GPU 提供的张量核心训练精度 |
| FP4              | 4 bits  | 一些研究型低精度格式        |

FP32 浮点格式：

$$
x = (-1)^s\cdot (1.m)\cdot 2^{(e-127)}
$$

FP16：

$$
x = (-1)^s\cdot (1.m)\cdot 2^{(e-15)}
$$

位宽越小 ⇒ 可表示的数更稀疏 ⇒ 精度下降 ⇒ 存储变少。

浮点精度就像**量杯刻度越细、量出来越准**：

- FP32 = 有 **毫升刻度** 的量杯
- FP16 = 只有 **1 厘米刻度** 的量杯
- FP8 = 刻度更粗，只能估大概

模型内部计算更精细 → **更准但更慢、更占显存**
精度降低 → **稍微不准一点，但速度快、显存小**

# 2. 量化（Quantization）

量化指的是把原来连续的浮点数 “压缩成” 更少比特的整数存储 / 计算。
即量化不是浮点格式，而是**把连续值强制映射到一组有限的离散值**。
常用为 int8、int4：属于整数量化。

## 2.1 数学表达

以对称量化为例：

$$
x_q = \text{round}\left(\frac{x}{s}\right)
$$

$$
x \approx s \cdot x_q
$$

其中：

- $x$ 原始权重（FP16 / FP32）
- $x_q$ 量化后的整数（int8 / int4）
- $s$ 是 scale（标定范围）

int8 × scale ≈ FP16

## 2.2 量化后的推理计算

推理时大部分计算使用 int4 / int8，最后在 matmul 输出阶段再恢复到 FP16。

量化就像：**把高分辨率照片压缩成只有 8 色或 4 色的低色深图片。**

- 原图（FP16）有 65536 色
- 量化成 256 色（INT8）
- 再量化成 16 色甚至 8 色（INT4 / INT3）

虽然图片仍能看出来是什么 → 模型仍能推理\
但细节会丢 → 能力可能略下降

# 3. 量化与浮点精度的区别（核心差异）

| 概念                   | 发生在哪里   | 本质是什么     | 损失程度          |
| -------------------- | ------- | --------- | ------------- |
| **精度（Precision）**    | 计算过程    | 换更低位浮点数   | 损失较小（连续 → 连续） |
| **量化（Quantization）** | 存储与部分计算 | 浮点 → 整数压缩 | 损失更大（连续 → 离散） |

精度是 “精确到多少位的数字”；
量化是 “把数字从浮点压缩成整数”。
精度降低影响小，量化影响大但节省得更多。

# 4. 显存消耗的差异（这是你最关心的）

## 4.1 模型权重占用

假设 7B 参数：

### FP16

$$
7\times 10^9 \text{ params} \times 2 \text{ bytes} \approx 14\text{ GB}
$$

### int8

$$
7\times 10^9 \times 1 \text{ byte} \approx 7\text{ GB}
$$

### int4

$$
7\times 10^9 \times 0.5 \text{ byte} \approx 3.5\text{ GB}
$$

# 5. 为什么量化能让 7B 在 24GB 轻松运行？

你推理还需要：

- KV Cache (大概每生成 1 token ≈ 0.7–1.0 MB 对于 7B）
- 激活（模型 forward 的中间张量）
- 框架开销、CUDA 内存池

估算：

### FP16（14GB 权重）

$$
14\text{GB} + 4\sim6\text{GB(缓存+激活)} \approx 18\sim20\text{GB}
$$

→ **24GB 够，但很紧**

### int4（3.5GB）

$$
3.5 + 4\sim6 \approx 8\sim10\text{GB} \ll 24\text{GB}
$$

→ **轻松运行，能开更长 context**

# 6. FP16 与 int8 / int4 模型精度对比

| 格式        | 推理质量损失 | 速度 | 显存省多少 |
| --------- | ------ | -- | ----- |
| FP32      | 无      | 最慢 | 0%    |
| FP16/BF16 | 极低     | 快  | 50%   |
| int8      | 小      | 更快 | 75%   |
| int4      | 中      | 最快 | 87%   |

LLM 的质量顺序大致：

**FP16 ≈ BF16 > int8 > int4 >> int2**

目前最常用 **int4 + GPTQ 或 AWQ**，在大多数任务中基本保持 FP16 的风格与语义能力。

# 7. 量化是否会 “破坏模型”？

不会破坏，只是改变权重精度。
但有几点要注意：

1. **量化后不可训练**（训练需要浮点）
2. 对特殊任务可能损失精度
3. 部分层不能量化（如 layernorm、embedding）

# 8. 量化和 float 精度有什么区别？

总结：

- **浮点**：指数形式，动态范围广，连续精度高。
- **量化**：用更少 bit 保存值，节省显存，提高速度，但有量化误差。

# 9. 量化可以用于训练模型吗？

可以用于训练，但取决于量化方式。\
严格来说：多数推理量化（如 int8、int4 GPTQ / AWQ）不能直接用于继续训练；\
但存在专门设计的 “可训练量化”（如 QLoRA 的 NF4、FP8 训练）。

| 量化类型                                          | 常见格式                                    | 能否继续训练？         | 用途                 |
| --------------------------------------------- | --------------------------------------- | --------------- | ------------------ |
| **推理量化**（Post-Training Quantization, PTQ）     | int8、int4（GPTQ、AWQ、bitsandbytes int8/4） | **不能**          | 推理（inference-only） |
| **训练友好量化**（Quantization-Aware Training / QAT） | FP8、int8-QAT                            | **可以**          | 微调或从头训练            |
| **参数低精度存储，但训练仍 FP16**（如 QLoRA）                | NF4（4bit NormalFloat）                   | **可以（LoRA 方式）** | 高效微调               |
| **FP16 / BF16**                               | 浮点格式                                    | **完全可以训练**      | 标准训练               |

所以，“量化后不能训练” 只对 **PTQ 推理量化**成立。

## 1. 为什么多数量化模型不能训练？

以 GPTQ/AWQ/int4 为例：

### 原因 1：梯度无法在整数域中传播

int4 / int8 权重是离散值，优化器更新连续值会破坏离散性。训练需要：
$W\_{t+1} = W_t - \eta \nabla W$
但量化权重 $\hat W$ 是离散的：

- 更新后需要重新量化
- 会造成震荡、发散

### 原因 2：现代 PTQ 量化（GPTQ / AWQ）依赖校准误差最小化

例如 GPTQ 做矩阵级别的最优量化：
$\hat W = \arg\min\_{\text{INT4}} |W - \hat W|\_2$
训练会立即破坏最优性，使量化结构失效。

### 原因 3：有些层被冻结（如 LayerNorm / Embedding）

GPTQ / AWQ 都默认不量化 LN、Embedding\
训练需要更新这些参数，但量化格式并不包含这些结构的梯度信息。
所以：GPTQ / AWQ 模型无法继续训练，也无法微调，只能推理。

## 2. 哪些量化模型可以继续训练？

### (1) QLoRA（NF4 + FP16）可以训练

QLoRA 经典方案：

- 权重存储：NF4（4bit NormalFloat）
- 前向计算：FP16
- 反向梯度更新：LoRA ΔW（FP16）

即：

> 主权重 NF4 不更新，只更新 LoRA。

所以 QLoRA 是最成熟的 “可训练 4bit 模型”。

### (2) FP8 训练（H100 + 新软件栈）可训练

FP8 有两种格式：

- E4M3（训练权重）
- E5M2（激活）

NVIDIA Transformer Engine 支持：

> 完整 FP8 训练、微调，全程可导。

在 H100 上，这已经是主流（Llama3 / 4 的部分训练阶段使用 FP8）。

### (3) int8 QAT（Quantization-Aware Training）可训练

流程：

1. forward 在 int8 量化
2. backward 在 FP16
3. 参数在 FP16 更新后再模拟为 int8

这种是用于部署前微调的，可训练，但需要特殊的 graph rewrite
